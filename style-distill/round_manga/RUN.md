# round_manga · 运行记录

## 任务
把【人物图】的角色与构图，改成【画法图】的**黑白漫画原稿**画法。
人物保持人物图的人物；动作允许微调；动作的基本含义不得改变。

## 输入
| 槽位 | 文件 | 尺寸 | 短哈希 | 承担角色 |
|---|---|---|---|---|
| 图1 | `input/A_char.png` | 1200×1348 | `e00509c4924b` | 人物、身份、服饰、道具、字幕、两格构图的唯一来源 |
| 图2 | `input/B_manga.png` | 1200×998 | `8df2baf3699e` | 只提供线条／明暗／网点／细节密度的画法 |

核验：两图哈希不同、非同一文件；图2 的附件与 `图生图用\1789604902823.png` 是同一文件（哈希一致）。

## 投喂版本（为过接口体积上限而做）
`work/feed_A.png` = A 加 1.4px 高斯模糊；`work/feed_B.png` = B 加 0.9px 高斯模糊。
合计发送 **1,473,040 字节（1.40 MiB）**。
依据：`normalise_to_size` 会把每张统一缩放到 1024×1024 再编码，按源分辨率压缩无效；
真正有效的是压掉画面高频细节。已知 1.67 MiB 通过、2.12 MiB 被拒（400 form field too large）。

## 提示词
`prompt_cn.txt`

## 生成
| 项 | 值 |
|---|---|
| 接口 | `image-direct.geiliapi.com/v1/images/edits`（经工作区既有管线 `compose/images/gen.py`，包装器 `../round_lib/gen2.py`） |
| 模型字段 | `gpt-image-2` |
| 尺寸 / 质量 / pad | `1024x1024` / `low` / `crop` |
| 上传顺序 | image = `feed_A.png`（人物图）→ image[1] = `feed_B.png`（画法图） |
| 耗时 | HTTP 200，58.5 秒 |
| 结果 | `out_r1.png`，1024×1024，2730 KB |

```
全图平均彩度：目标 27.2  结果 0.9      ← 确认已是干净的灰度，无半褪色浑浊态
```

## 本轮显式让出的规则（重要，复现时必须照做）
风格参考本体是**无彩色**，照搬必然去色，这与 R1"只迁手法不迁配色"及负向必含的
`monochrome conversion` / `full greyscale` 直接冲突。
本轮处理：
1. **把这两条从必含 7 条里移除**（否则正负互斥，结果会卡成半褪色的中间态）；
2. 整层"色彩守卫"替换为**中性灰守卫**：不要任何色相、不要暖黄／偏褐／偏蓝、不要滤镜式单色染色；
3. 在提示词正文里写明这是**显式授权**（"本次是有意去色，其它任何情况下都不得去色"）。
