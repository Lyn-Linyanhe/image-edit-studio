# 风格蒸馏 · 通用流程（SOP）

> **本文档是什么**：把「提取 / 蒸馏 / 改图」拆成**有门禁的阶段流程**——每步的输入、执行方、产物、
> 通过条件、以及**不通过时回退到哪一步**（不是从头重来）。
>
> **与其它文件的分工**（各一份，互不重复正文）：
> | 文件 | 角色 |
> |---|---|
> | **本文件** | 顺序 · 产物 · 门禁 · 返工矩阵（**先看这份**） |
> | `风格提取蒸馏_单条提示词.md` | **随手可用的一条提示词**（压缩版；正式建库仍走本流程） |
> | `风格提取蒸馏_通用模板.md` | 各阶段可粘贴的提示词与槽位 |
> | `风格提取提示词_v2.md` | 模式 A（单图提取）的 A–G 契约正文 |
> | `风格提取提示词_评审.md` | 为什么这么设计（依据与证据） |
> | `漫画风格蒸馏.md` / `style_card.json` / `img2img_方案.md` | 一次真实执行的结果（实例） |

## 0. 全景图

```
┌── 一次性建库（每个风格只做一次）──────────────────────────────────────────┐
│  0 取材分组 → 1 观察 → 2 裁决 → 3 半风格决策(人) → 4 定量+证伪 → 5 组装    │
│    人+脚本    模型     模型      ★唯一强制人工   脚本        模型+人        │
└──────────────────────────────┬────────────────────────────────────────────┘
                               ↓  产出：style_card + 阈值区间 + E 段提示词
┌── 每次改图（复用同一份规范，不必重新蒸馏）────────────────────────────────┐
│  6 出图（人+接口） → 7 验收 ──通过──→ 归档到 产图\<style_id>\              │
│                      └──不通过──→ 按第 5 节返工矩阵回退到指定阶段          │
└───────────────────────────────────────────────────────────────────────────┘
```

**两条泳道不要混**：建库是"一次性、慢、要人决策"；改图是"可重复、快、只跑 6–7"。每次改图都重新蒸馏一次，
是最常见的浪费。

## 2. 阶段 0 · 取材与分组（人 + 脚本）

**动作**
1. 按"同一作者 / 同一系列 / 同一媒材"初分组。**每组 ≥6 张**，并尽量覆盖该风格的**两端**（最淡的一张与最艳的一张）。
2. `python style-distill/analyze_style.py <组目录> -o .../00_stats.json`
3. 看三件事：`aspect_all` 是否统一；`per_image` 里的 `sat_mean_content` / `val_mean_content` / `edge_density`
   是**成簇**还是**连续分布**；有没有明显异类。

**门禁 G0**
- [ ] 画幅口径一致（`aspect_all` 只有一两种值）
- [ ] 组内关键指标**成簇**；若明显分成几簇 → **拆组**，按支系分别蒸馏
- [ ] 组内**不含**异风格图（见下方 ⚠️）

**⚠️ 最容易搞错的一条**：**参照图（异风格图）绝不能放进蒸馏组目录**。它会把 `palette_top10`
和所有 `*_mean` 一起污染。参照图必须**单独跑一遍**，只用于阶段 4 的证伪。
> 本仓库 `漫画风格蒸馏.md` 第 233–245 行是把两者一起送进去的——那一次只用于**对比证伪**，
> 它的数值不能当作"同一风格的聚合阈值"。两者用途不同，别混用。

**阈值口径纪律**：同一风格内部离散是真实存在的（本仓库实测饱和度跨度 **0.032–0.148**），
所以阶段 4 的阈值一律用 **min–max 区间**，不要用均值单点。

**回退**：成簇 → 拆组重跑 0；有异类 → 移出该组（或另立一组）。

## 3. 阶段 1 · 观察（模型）

用 `风格提取蒸馏_通用模板.md` 的对应段落：单图用模式 A，成组用模式 B 的 B-1…B-3。

**门禁 G1**
- [ ] 7 个维度齐（艺术风格 / 主体与场景 / 构图与视角 / 色彩搭配 / 光影表现 / 材质与细节 / 情绪与氛围）
- [ ] 色彩搭配**分了两行**：4a 固有色相（默认不迁移）/ 4b 色彩处理手法（可迁移）
- [ ] 每项都有【依据】（位置、面积占比、可测倾向）
- [ ] 无"高级感""氛围感强"这类无效词
- [ ] 无编造的作者 / 年代 / 模型 / 镜头 / 制作流程

**回退**：缺依据 → 只让它补依据重出该段，**不要自己替它写**（自己写会把自己的先验当成画面证据）。

---

## 4. 阶段 2 · 裁决（模型）

产出四分类：🔵 手法（可迁移）/ 🟠 内容（禁搬）/ 🟡 半风格（需人决策 + 代价）/ 🔴 不可迁移（身份、署名）。

**门禁 G2**
- [ ] 这五项**各自单独一行**，不得省略：**留白比例 · 背景处理 · 画幅与景别 · 整体明暗档位 · 署名与水印**
- [ ] 每个 🟡 都写明了"迁移后的效果"与"代价"
- [ ] 规则落地：**凡未判为 🔵 的项，一律不得进入阶段 5 的 C 段与 E 段**

**回退**：有项未分类 → 补判。**不得带着未分类项进入阶段 3。**

---

## 5. 阶段 3 · 半风格决策（人）★ 唯一的强制人工决策点

**输入**：阶段 2 里所有 🟡 项。**输出**：逐项勾选"迁移 / 不迁移"，并记下代价。

| 决策项 | 迁移后的效果 | 代价 |
|---|---|---|
| 留白倾向 | 画面更空、空气感更强 | 会改变目标图的背景内容 |
| 背景处理（保留 / 换纯白纸底） | 换白底 = 最硬的风格特征之一 | 目标图原有环境元素全部丢失 |
| 画幅与景别（是否强制 3:4 单人半身居中） | 构图更像参考图 | **必然重排目标图**：人物位置、裁切、手与道具全变 |
| 整体明暗档位（是否抬暗部、消灭黑） | 拿到"高调无黑" | 目标图原本暗部重时，体积感与厚重感被明显削平 |
| 署名与水印 | —— | **永远不迁移**（不得复刻他人署名） |

**门禁 G3**：每项都已勾选；**留空 = 按"不迁移"处理**（不允许悬空）。

**回退**：决定不了 → 先用预览工具看代价，再决定：
```powershell
python style-distill/one_preview.py <目标图> --floor 0.40 -o tone_preview.png
```

## 6. 阶段 4 · 定量与证伪（脚本）

```powershell
# ① 先自检 Lab 实现（本仓库踩过坑：PIL 的 LAB 转换不可靠，已改自实现并自检）
python style-distill/analyze_style.py --selftest

# ② 量蒸馏组
python style-distill/analyze_style.py <蒸馏组目录> -o .../40_stats.json

# ③ 参照图单独跑（必须与 ② 分开跑）
python style-distill/analyze_style.py <参照图目录> -o .../40_foreign.json
```

把 `aggregate` 里的字段填进 B-6 的"待实测"，写成 **min–max 区间**：
`paper_white_ratio_mean` `lum_p05_mean` `lum_p95_mean` `val_mean_content_mean` `val_std_mean`
`sat_mean_content_mean` `sat_p90_content_mean` `contrast_range_mean` `edge_density_mean`
`wash_ratio_mean` `lab_b_mean_mean` `hue_family_mean`（`palette_top10` **仅描述性证据，不是迁移目标**）。
`per_image` 用来看离散，"我要不要拆组"就靠它。

**门禁 G4**：逐个指标写明结论——**"判别力已验证"或"作废"**；未通过证伪的**不得写进验收线**。

**参照法（不可跳过）**：凡"蒸馏组"与"参照图"数值接近的指标，说明它分不开两种风格，一律作废。
> 本仓库据此作废了三个看着最像"风格特征"的指标：**内容饱和度、b\* 色温、笔触密度**。
> 留下的是 **留白占比、最暗值下限、整体明度**。

**口径警告（实测发现，引用时必须写口径）**：`analyze_style.py` 第 198 行的留白掩膜阈值是 **0.94**，
而 `漫画风格蒸馏.md` 第 65 行同时给了 >0.97（42.5%）与 >0.94（51.0%）两个口径，
第 236–245 行表里标着 ">0.97" 的 0.503/0.520 从数值看更接近 0.94 口径。
**不写口径，"≥0.35"这条线对哪个口径成立就说不清。**

**回退**：若所有候选指标都被证伪 → 说明该风格在可测层面与参照图无差别，
退到"人眼比对 + 半风格项"路线，并在验收线里**明确标注"本风格无可用量化验收线"**，不要硬编一条。

## 7. 阶段 5 · 组装规范卡与提示词（模型 + 人）

把 1–4 的结果落成：`style_card.json` 字段（沿用现有 schema）+ B-4 标签 + B-5 负向守卫 + E1/E2/E3 三版提示词。

**门禁 G5**
- [ ] 自检 5 问全过（无内容名词 / 无 hex 与色板名 / 不一致项已列 / 五项已单列 / 无编造）
- [ ] C 段无内容名词、无 hex、无色板名
- [ ] E 段有"这是一次风格迁移，不是重新设计"的声明 + 逐项 PRESERVE 清单
- [ ] 负向守卫 7 词齐全；背景清除词按**档位**分流（保背景→剔除；换白底→可加）
- [ ] 阈值区间与阶段 4 一致（含口径说明）

**回退**：自检不过 → **只重出对应那一段**，不要把全文重出（重出会引入新的漂移）。

## 8. 阶段 6 · 出图（人 + 接口）

按 `{接口}` 走：
- **edits 类**（参考图 + 目标图 + 文本，无 denoise、无独立负向）：上传顺序在文本里点名；尺寸跟随**目标图**；
  负向用正文的 DO NOT INCLUDE 段替代。

- **纯文生图**：直接用 E1 正向段；此场景写死色板是允许的。

## 9. 阶段 7 · 验收与返工

```powershell
python style-distill/analyze_style.py <输出图目录> -o .../70_new_stats.json      # 对照阶段 4 的区间
python style-distill/compare_identity.py <目标图> <输出图>                        # 身份漂移
python style-distill/preserve_hue.py --style-output <生成图> --original <目标图> -o <输出>   # 色相兜底（可选）
```

**门禁 G6**：三条命令的结论都写下来（数值 + 判定），**不要只写"看起来可以"**。
`preserve_hue.py` 的前提别忘：色相取自目标图**同位置**像素，生成图与原图几何位移大时会错位
（实测过把参考图道具的红色错位糊到人体上）；位移很大时不适用。

## 10. 返工矩阵（不通过时回哪一步）

| 症状 | 归因 | 回退到 | 动作 |
|---|---|---|---|
| 发色被漂白、饰品消失/变多、小痣数量变了 | STYLE 段过长压过了 PRESERVE；负向缺守卫 | **阶段 5** | 缩短 STYLE、把 PRESERVE 提到第一句、补齐 7 个守卫词 |
| 反复改仍在漂 | 纯文本约束的上限 | **阶段 6** | 上 `preserve_hue.py`（注意几何前提）或加 ControlNet / IPAdapter |
| 目标图的背景被删空 | 负向里含背景清除词 | **阶段 5** | 按档位分流，剔除背景清除词，背景只靠正向从句 |
| 构图被重排（人物换位、裁切变了） | 构图被误判成 🔵 | **阶段 2** | 重新裁决为 🟠；E1 的 PRESERVE 补上构图与裁切 |
| 过曝 / 过灰 / 脏 | 参数 | **阶段 6** | 降 CFG；负向补 `dirty gray` `noise` |
| 风格没上到位 | 标签太泛 | **阶段 5** | 换更具体的媒介术语重出 C 段；仍不行 → **阶段 6** 加图像条件 |
| 验收线测不出差异 | 阈值未经证伪 | **阶段 4** | 重做参照法；作废无判别力指标 |
| 组内风格不一致、阈值区间宽得没用 | 分组错 | **阶段 0** | 拆组，或用"支系"分别蒸馏 |

## 11. 失败模式库（全部来自本仓库实测）

| # | 失败模式 | 判据（怎么发现的） |
|---|---|---|
| 1 | **身份漂移** | `compare_identity.py`：发区明度过高=发色被漂白；高饱和蓝为 0=眼睛/羽毛/宝石被褪色 |
| 2 | **明暗抬过头（过曝）** | 实测：明度 0.480→0.864（风格上限 0.744）；P05 0.292→0.693（上限 0.616） |
| 3 | **色相泄漏** | 把参考图的 hex 写进改图 prompt → 目标图发色被换 |
| 4 | **去色变黑白** | 把"低饱和"执行过头；负向缺 `monochrome conversion` / `full greyscale` |
| 5 | **背景被负向误删** | 负向区分不了"不要新增"和"删掉已有的" |
| 6 | **阈值幻觉** | 模型自己"估"出指标数值 → 必须由脚本实测回填 |

## 12. 停止条件（什么时候别再调提示词）

- 同一张图连改 **3 轮**仍在身份漂移 → 转脚本兜底或结构锁，不要继续调措辞。
- 参照法证伪掉**全部**候选指标 → 转人眼比对 + 半风格决策，不要硬编验收线。
- 找不到 **≥6 张**同风格图 → 只做模式 A（提取），不做蒸馏。
- 参考图与目标图**先验高度重合**（例如都是浅发少女半身像）→ 换基准图，或接受更高的漂移风险
  （选基准图的四个轴：先验重合度、色相外泄、笔触密度、前景手势/道具泄漏）。

## 15. 已知边界 / 本文件未做的事

- **单图不能蒸馏**（组内离散 0.032–0.148，抽一张必偏）；单图只走模式 A。

- **阶段 3 必须由人做**：这是设计上的停顿点，不是流程缺陷。
- **本文件未做**：没有重跑任何生图、没有新增或修改任何脚本、没有改动任何既有文件
  （`git status` 只有 `风格提取提示词_评审.md`、`风格提取提示词_v2.md`、`风格提取蒸馏_通用模板.md`、本文件四个新增文件）。
