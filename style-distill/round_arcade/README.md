# round_arcade · 换人重画（动作/环境取图1、人物与风格取图2）

**任务**：参照第一张图的人物动作及环境，把主角换成第二张图的人物；**风格参照图为图二，不改变风格**。

## 输入（`input/`）

| 文件 | 来源 | 尺寸 | 角色 |
|---|---|---|---|
| `A_pose_env.png` | 图1 原图 | 1200×1542 | 动作 + 环境（原始） |
| `C_pose_env_2x3.png` | 图1 预裁 2:3 | 1029×1542 | **投喂用**内容图（体积规则 4：投喂前自己裁成目标比例） |
| `B_char_style.png` | 图2 原图 | 1200×1200 | 人物身份 + 渲染手法（参考图） |

同质性核验（`audit_and_check.py audit`）：两图哈希不同，**不是自我迁移**；
没有任何一张同时充当"身份源 + 姿态源"。

## 角色分配表

| 图 | 提供什么 | 不提供什么 |
|---|---|---|
| 图1（内容） | 构图、人物位置与朝向、**动作与手势**、街机环境全部元素、**环境的全部颜色**、画幅 | 原主角的角色设计（金发／猫耳兜帽／护目镜帽／耳机／粉紫夹克） |
| 图2（参考） | **人物身份**（脸、发、头饰、颈饰、服装）＋**全部渲染手法** | 它的场景与道具（LOVE NOTE 本子、纯白背景）、它原本的姿势与表情 |

## 提示词

`prompt_arcade_v1.txt` —— 六块骨架（HEAD / PRESERVE 🔒 / 人物 🔒 / 动作 🔒 / 渲染手法 🔒 / 色彩规则 / DO NOT INCLUDE）。
`lint_prompt.py` 结果：**五项全过**。

## 第一轮（2026-09-22）

参数：`--size 1024x1536 --encode jpg`（**JPEG 投喂通道**，见下）
命令：`scripts/run_v1.ps1`（同提示词出 3 版择优，顺序跑以避免下载互抢带宽）

| 候选 | 生成耗时 | 取回 | 尺寸 | 结果 |
|---|---|---|---|---|
| `out_v1_r1.png` | 185.9 s | 216 KB/s / 10 s | 1024×1536 | 构图偏小、白裙像连衣裙 |
| `out_v1_r2.png` | 69.6 s | 首试 0 B/32 s 淘汰 → 46 KB/s / 50 s | 1024×1536 | 人更近、手势清楚；左前臂有一处杂线 |
| `out_v1_r3.png` | 51.3 s | 230 KB/s / 9 s | 1024×1536 | **构图与人物质感最均衡（推荐候选）** |

三版调子剖面高度一致（彩度 15.6 / 16.6 / 16.7，平均亮度 0.56–0.57），说明这版提示词的结果稳定，
**方差主要落在构图尺度与手部细节上**。

## 本轮的两个接口结论（已写进 `pipeline-notes.md`）

1. **JPEG 投喂通道**：同一尺寸同一对图，**PNG 2.80 MiB → JPEG 0.56–0.66 MiB（约 5 倍）**；
   中转站**接受 JPEG 上传**（三版全 HTTP 200、尺寸精确遵守）。加 `--encode jpg` 即可，无需走压缩梯子。
   这解开了"2K/4K 只能把身份参考压成 448px+模糊+128色（脸不像的根源）"这个死结。
2. **结果 CDN 多网关**：同一轮三次调用落在 `v4-gateway-v2.shagentai.com`、`api.mikoto.vip`、
   `v4-gateway-v1.shyfai.cn` 三个域名上——**不要把域名写死**。

## 第二轮：提高人物辨识度（2026-09-22，只动"人物身份"一个模块）

用户反馈：**第一轮的 r1 画风可用，但人物辨识度还可以（不够）**。
对策用上了同年当天打开的 **JPEG 通道**——它腾出的额度让"再加一张图"成为可能：
新增 `input/D_face_closeup.png`（从图2 裁出的**脸部特写** 980×924，覆盖皇冠/粉云/两枚发夹/向日葵/
整张脸/颈饰）。三图合计仍只有 **0.79 MiB**（若用 PNG 会是约 3.7 MiB，根本放不下）。

提示词按模块化派生（`scripts/make_prompts_v2.py`，锚点命中数断言为 1）：
`prompt_arcade_v2.txt` = v1 逐字不变 + ①"第三张图＝同一角色的脸部特写"的声明
+ ② 一段**带几何锚点的身份项**（脸型/眼型与虹膜双层结构/睫毛/眉毛/鼻的极简处理/嘴/雀斑与腮红/
发量与分缝/发色与排线/四件身份标记）+ ③ 身份漂移负向。
`prompt_arcade_v3.txt` = v2 + 图2 招牌的"单眼眨 + 得意微笑"。两者都过 `lint_prompt.py` 五项。

| 候选 | 用的提示词 | 变量 | 生成/取回 | 结果 |
|---|---|---|---|---|
| `out_v2_r1_v1prompt_faceref.png` | v1 | 只加脸特写 | 67.2 s / 90.8 KB/s | 双眼睁开看观者；身份明显变准 |
| `out_v2_r2_idanchor.png` | v2 | +身份锚点 | 44.7 s / 首试 4.0 KB/s 淘汰 → 116 KB/s | 出现眨眼（见下注）；发量与虹膜结构最好 |
| `out_v2_r3_idanchor.png` | v2 | 同上（第二采样） | 66.3 s / 273.9 KB/s | 未眨眼、视线偏向机器；构图最稳 |
| `out_v2_r4_wink.png` | v3 | 显式要求眨眼 | 51.4 s / 81.1 KB/s | 眨眼＋得意微笑，识别度最高 |

> **注（本轮的实验设计失误，如实记录）**：v2 的"身份项"里有一条在描述**图3 里闭着的那只眼**
> （"上弯的弧线 ^ 形"），这条本身就把眨眼带进了提示词——所以 **r2 也眨眼了**。
> 于是 r2/r3 与 r4 之间**不再是"表情"这一个干净变量**。下一轮若要做表情 A/B，
> 应把"闭眼那只是图3 的姿态特征，不是身份特征"从身份项里拆出去。

调子剖面四版一致（彩度 18.5–20.3、平均亮度 0.51–0.58，无褪色），比第一轮的彩度 15.6 更实。
