# 风格提取提示词 · 评审（7 维框架版）

**被评审对象**：一份通用的「看图 → 分析视觉风格 → 提炼生图提示词」提示词。结构为 4 段——
① 风格概述（2–3 句）② 视觉元素拆解（7 维：艺术风格 / 主体与场景 / 构图与视角 / 色彩搭配 /
光影表现 / 材质与细节 / 情绪与氛围）③ 核心风格关键词（中英对照，区分主体内容词与风格描述词）
④ 可直接使用的生图提示词（原图还原版 + 风格迁移版占位符版）。

**评审目的**：判断它能否用于「提取图片绘画风格」并**用于图生图改其他图**（保内容、换风格）。

**相关文件**：`style-distill/漫画风格蒸馏.md`（第二代拆解依据）、`style-distill/img2img_方案.md`（迁移方案）、
`compose/style_prompt_final.md` 与 `compose/style_templates.md`（第一代提取提示词）。

---

## 0. 一句话结论

> **它是一份合格甚至优秀的「观察层」提示词，但不是一份可用的「改图层」提示词。**
> 直接用它的输出做图生图，会命中本仓库已经实测翻过一次车的那几个点——因为它的 7 维框架里，
> **没有任何一项告诉你「这条特征该不该迁移」**：7 维全是"描述"，而改图需要的是"裁决"。

**证据**：这份提示词正是 `漫画风格蒸馏.md`（第 9–18 行）反复引用的「你给的 7 维度框架」那一代原始版本；
仓库后来在它之上补出的核心成果，就是把"描述"升级成"裁决"——即铁律 A（`img2img_方案.md` 第 12–30 行）。

## 1. 判据表：什么场景能用

| 用途 | 判定 | 依据 |
|---|---|---|
| 人看的风格简报 / 沟通对齐 | ✅ **可直接用** | 结构完整；明确禁止堆砌"高级感/高质量"；明确禁止把推测的作者、模型、镜头参数当事实；明确声明"不恢复原始提示词"——这三条纪律是对的 |
| 文生图复刻**参考图本身** | ✅ **基本可用** | 此场景写死色板与构图是对的（同 `style_prompt.md` 第 62–64 行的结论：文生图时带色板正确） |
| 建风格库前的**第一批人工观察稿** | ✅ **可用**（建议多图聚合） | 7 维覆盖面无遗漏；但单图结论不能当作风格级结论，见第 3 节缺口 ④ |
| **图生图改另一张图（保内容换风格）** | ❌ **不能直接用** | 4 个缺口，见第 3 节 |
| 批量化 / 脚本化 / API 调用 | ❌ **不适用** | 输出是散段落 + 中英混排，无固定 schema，`json.loads` 拿不到东西 |

**一句话**：把它的产出当作 `漫画风格蒸馏.md` 的**输入稿**是对的；当作 `img2img_方案.md` 的**替代品**是错的。

## 2. 7 维逐项归属（核心表）

改图的唯一纪律是：**每条特征必须先判定归属，再决定写不写进 prompt**。
下面把 7 个维度逐项拆开（依据来自 `漫画风格蒸馏.md` 第 8.1/8.2 节与 `img2img_方案.md` 第 0 节）：

| 你的 7 维 | 归属 | 依据 |
|---|---|---|
| **艺术风格**（媒介/技法） | 🔵 **手法**，无条件迁移 | 这是风格本体；"模拟传统媒材"这类判定是可用信息 |
| **主体与场景** | 🟠 **内容**，禁搬 | 抱书 / 扶手 / 圆框眼镜 / 水手服 / 道具是"人物专属或内容"，搬过去会改掉目标图的人物与画面 |
| **构图与视角** | 🟠 **内容**，禁搬 | 3:4 竖幅、单人、半身胸像、居中、裁切位置——写着就会强制重排目标图（`img2img_方案.md` 第 42–52 行） |
| **色彩搭配 · 主色/辅助色（色相族、hex）** | 🟠 **内容**，禁搬 | **铁律 A**：固有色相不迁移。参考图的 10 个 hex 只能当"饱和度 0.085"的描述性证据（`img2img_方案.md` 第 83 行） |
| **色彩搭配 · 饱和度/对比度/明暗关系** | 🔵 **手法**，可迁移（带张力） | 但它与"色彩不动"有冲突，需选档：1A 全风格 / 1B 半风格（`img2img_方案.md` 第 55–68 行） |
| **光影 · 光源方向 / 软硬 / 有无投影** | 🔵 **手法** | "正面偏上、极软、无落地投影、无体积光"是判别特征 |
| **光影 · 暗部用灰紫、高光用纸白** | 🟠 **色相**，禁搬 | 改为**从每个元素自身色相派生**（`img2img_方案.md` 第 90 行、第 102–104 行） |
| **材质与细节 · 笔触/渗染/颗粒/清晰度** | 🔵 **手法** | 铅笔断线、叠线重描、水彩渗染、柔边——这是核心可迁移项 |
| **材质与细节 · 细节密度** | 🔵 **手法** | "选择性细致"（眼与发丝密、衣料背景概括）可迁移 |
| **情绪与氛围** | 🟡 **低信号，必须先转换** | 生成模型对"安静/温柔"几乎不响应；仓库的做法是把情绪映射到可测手法表（`漫画风格蒸馏.md` 第 164–172 行：安静←留白 42.5%、温柔←低饱和+高调+低对比……） |
| **（你的框架未覆盖）色彩搭配的"手法 vs 固有色相"分界** | 🔴 **缺失项** | 见缺口 ① |
| **（你的框架未覆盖）留白 / 纯白背景** | 🟡 **半风格**，需你决策 | 纯白占画布 42.5%（第 65 行）是这套风格最硬的判别特征，但它同时改变了目标图的背景内容——`img2img_方案.md` 第 41 行明确把它列为"半风格" |
| **（你的框架未覆盖）身份细节与作者署名** | 🔴 **负向守卫 + 像素兜底** | 发色、饰品、小痣是身份点；画面左下/右下有作者中文署名（`漫画风格蒸馏.md` 第 41 行、第 189 行），**不得复刻** |

**统计**（按 7 个维度算）：**2 个整体属手法**（艺术风格、材质与细节，其子项全为 🔵）；
**4 个需要拆分或整体拒搬**（主体与场景、构图与视角整体是 🟠 内容；色彩搭配与光影表现各含"手法"与"色相"两半，
必须拆开写）；**1 个低信号需转换**（情绪与氛围）。另有 **3 类框架未覆盖的项**（迁移分界、半风格项、身份与署名）。

## 3. 四个缺口与证据

### 缺口 ① · 没区分「固有色相」与「色彩处理手法」→ 色相泄漏

你的提示词第 2 节要求输出「主色、辅助色」，第 4 节又要求把这些写进"可直接使用的生图提示词"。
这条链路的终点，就是本仓库实测翻车的地方：

| 项目 | 目标图 | r1 输出 | 判定 |
|---|---|---|---|
| 发色（发区均值） | 灰褐带黄绿 `#8C8C83` | 近白亚麻白 `#F1EDE5` | ❌ 被漂白 |
| 眼睛 | 亮青蓝，饱和度 0.386 | 灰蓝，饱和度 0.257 | ❌ 被褪色 |
| 高饱和蓝占比 | 0.132% | **0.000%** | ❌ 蓝眼/羽毛/宝石的辨识点全失 |
| 蓝像素总量 | 0.233% | 0.027% | ❌ 掉 8.6 倍 |

> 出处：`style-distill/target/r2_路线2_头部不动.md` 第 9–21 行（r1 失败诊断表）。

更关键的是，仓库还实测出一条反直觉结论——**"低饱和"根本不是这套风格的判别特征**：
异风格图的饱和度 0.077 恰好夹在本风格两张的 0.035 与 0.144 之间（`漫画风格蒸馏.md` 第 236–245 行）。
也就是说，**按"低饱和"这条外观印象去写提示词，既会泄漏色相，又抓不住风格**。

**修法**：参考图的 hex 一律只当"手法强度的描述性证据"，不进改图 prompt；暗部与高光改为从各元素自身色相派生；
负向必须带 5 个守卫词（`img2img_方案.md` 第 120–139 行）。

### 缺口 ② · 没有「手法 / 内容 / 半风格」的迁移边界

你的提示词要求把 7 维**全部**写进提示词（第 4 节"原图还原版"保留主体、场景、构图和风格）。
在改图场景里，这等于把内容一起搬过去。仓库为此刻意做过一张"不迁移清单"
（`img2img_方案.md` 第 38–46 行），里面明确禁止迁移：抱笔记本、扶手、圆框眼镜、水手服/毛衣/西装、
3:4 单人半身居中构图、纯白纸底、基准图的 10 色色板。

**还有一类更隐蔽的**：既不是纯风格、也不是纯内容，而是"改了就会动到目标图"的**半风格项**——
留白倾向就是典型。仓库的做法是显式列出并写明代价，而不是让它隐式生效
（`img2img_方案.md` 第 41 行把它标为"半风格：它同时改变了目标图的背景内容"）。

### 缺口 ③ · 没有验收、没有兜底、没有档位取舍

一个"能用于图生图"的提示词，输出里必须回答三个问题，你这份都没问：

1. **改到什么程度算达标？** —— 仓库的答案是三条硬指标（见第 5 节补丁 5），且明写哪些指标**不可用**验收。
2. **改不动怎么办？** —— 纯文本压不住低饱和高调这类特征时，要转 IPAdapter / 风格 LoRA；色相守不住时要上像素级兜底
   （`preserve_hue.py`，铁律 A 的物理兜底，`img2img_方案.md` 第 264–296 行），且它**有几何位移前提**——
   生成图与原图几何位移大时色相会整体错位（同一节记录：试过把红电话的红色错位糊到下巴和手臂上）。
3. **这次要哪一档？** —— 1A 全风格（抬暗部、无黑）还是 1B 半风格（只换笔触）；两档的代价完全不同：
   目标图原本暗部重的话，1A 必然削弱其体积感，这是**选择换来的代价，不是 bug**（`img2img_方案.md` 第 55–68 行）。

### 缺口 ④ · 单图分析不稳定 + 无结构化输出

同一风格内部，饱和度实测跨度是 **0.032 到 0.148**（三套色板分支：0.032–0.045 / 0.079–0.148 / 0.101–0.131，
`漫画风格蒸馏.md` 第 111–122 行）。所以**单张图给不出风格级结论**——你可能正好抽到最淡或最艳的那张。
仓库的做法是 13 张全量逐张拆解后取交集（`compose/style_templates.md` T5 同思路）。

另外，输出是散文段落 + 中英混排，脚本无法消费；仓库有 `style_card.json` 这类结构化产物，
说明这条路是必需的。

**修法**：多图聚合 + 固定 schema；schema 里**不要**用 `palette.primary: ["#hex"]` 这种字段——
它会直接诱发色相泄漏（见第 4 节），要改成 `paletteTechnique`（手法）与 `localHuePolicy`（禁改色相）。

### 附带三条小问题

| # | 问题 | 说明 |
|---|---|---|
| 1 | **"原图还原版"在已有原图时无意义** | 你手上就有那张图，图生图直接给图远比"用文字复现"精确；文本承载不了像素级细节。这版真正的价值是**自检**——拿来对照分析有没有抓住判别特征。"原图还原"只在文生图、且不想用参考图时才成立 |
| 2 | **情绪词对生成模型是低信号** | "安静温柔内敛的书卷气"几乎不改变输出。要按 `漫画风格蒸馏.md` 第 164–172 行那样把情绪落到可测手法上 |
| 3 | **"风格归类"有素材与事实双重边界** | 你这份已要求"不确定的标注、不要把推测的作者当事实"——这是对的，仓库同样只写"具体作者与作品系列未识别"（第 94 行）。但还要补一条：若参考图带作者署名水印（本套图占画幅宽 2–3%），**迁移时不得复制**，也不要把他人作品当自己的原创素材（第 189 行） |

**做对了的三件事**（值得在 v2 里保留）：① 第 3 节把"主体内容词"与"风格描述词"分开——这正是铁律 A 的雏形；
② 明确禁止堆砌"高级感/高质量"这类无效修饰；③ 明确声明"不恢复原始提示词、不虚构作者与镜头参数"。

## 5. 最小补丁清单（若你坚持直接用粘贴的那份）

不改它的结构，只加 5 条（另有 1 条可选）。**加完它在改图场景才勉强及格**（仍缺验收脚本与像素兜底）：

**补丁 1 · 色相锁**（插在第 4 节之前）
```
【色彩铁律】参考图的具体色相一律不得迁移。
- 目标图每个元素自己的颜色保持不变：头发、眼睛、肤色、每件衣物与道具、背景色相族。
- 参考图的 hex 只能作为"色彩处理强度"的描述性证据，不得作为迁移目标写进 prompt。
- 暗部与高光从各元素自身色相派生（该色相压暗降饱和 / 提亮），不要统一换成参考图的暗部色或纸白。
```

**补丁 2 · 迁移裁决**（改第 3 节，要求四分类）
```
除"主体内容词 / 风格描述词"外，再给每条特征标注迁移归属：
🔵 手法（无条件迁移）/ 🟠 内容（禁搬）/ 🟡 半风格（需用户决策，写明代价）/ 🔴 不可迁移（身份与署名）。
每条必须给出图中可观察到的依据；无法判断写"未识别"，不要猜。
```

**补丁 3 · 半风格项显式声明**
```
对下列各项单独输出一段【需你决策】，逐条写明"迁移后的效果"与"代价"：
留白比例 / 背景处理（保留 or 换纯白）/ 画幅与景别（是否强制 3:4 单人半身居中）/ 整体明暗档位
（是否抬暗部、消灭黑，代价是目标图的体积感被削弱）。
未明确声明前，一律按"不迁移"处理。
```

**补丁 4 · 负向守卫**（追加到负向段）
```
hue shift, recolouring, palette swap, wrong hair colour, colour cast toward grey-violet or blue-grey,
monochrome conversion, full greyscale
```
> 前 5 个防"发色被换成参考图的色"；后 2 个防另一个方向的翻车——把"低饱和"执行成"去色变黑白"
> （`img2img_方案.md` 第 137–139 行）。
> ⚠️ 若接口有独立负向通道，**不要**照搬 `compose/style_prompt_final.md` 第 72 行的标准底座里的
> `cluttered background` 等背景清除词——负向无法区分"不要新增"和"删掉已有的"，会把目标图自己的背景一起抹掉。
> 只有当你明确要"换成纯白纸底"时，这类词才可加；这条按**档位**分流，与接口有没有负向入口无关。

**补丁 5 · 验收三条**（追加到第 4 节之后）
```
【验收】改完后用可测指标核对，不要用肉眼"感觉像"：
1. 纯白(>0.97) 占比（判别力 ★★★：本风格 0.446–0.624，异风格 0.006）
2. 亮度 P05 / 最暗像素（★★★：本风格 P05 0.387–0.616、最暗 0.166–0.320）
3. 内容区域明度均值（★★：本风格 ≥0.60）
❌ 不要用"内容饱和度"或 b* 色温验收——实测无判别力（异风格 0.077 夹在本风格 0.035 与 0.144 之间）。
❌ 保留目标图背景时（方案一），不要用"纯白占比"验收，这条必然不达标。
```
> 出处：`漫画风格蒸馏.md` 第 236–257 行；`img2img_方案.md` 第 252–257 行；`target/prompt_三图_v3_纯白背景.md` 第 19、352 行。

**补丁 6（可选）· 多图聚合**：风格库场景下按 `compose/style_templates.md` T5 取交集，并列出"各图不一致、因此不得写入 prompt"的特征。

## 6. 评审的依据强度与不确定项

**有实测支撑的判定**（可直接采信）：
- r1 色相漂移的四项数字、判别力三项与两个"无判别力"指标、13 张饱和度跨度 0.032–0.148、
