# 风格提取提示词 v2 · 通用版（可直接粘贴）

> **适用**：任意参考图 → 提取可迁移风格 → 用于图生图改另一张图，或用于文生图建同风格新图。
> **通用**：不绑定本仓库那套水彩彩铅风格；那套只作为证据与示例在文末引用。
> **要填空复用、或要做"蒸馏"（多图 → 风格规范卡）** → 用 `风格提取蒸馏_通用模板.md`；
> **端到端流程（阶段顺序 · 门禁 · 返工矩阵）见 `风格蒸馏_通用流程.md`**——新任务从那两份进。
> **本文件是那份模板的模式 A 权威正文**（含槽位替换说明），两份文档不重复正文，因此不会出现分歧版本。
> **配套**：为什么这么改见 `style-distill/风格提取提示词_评审.md`；已落地到本仓库那套风格的实例见
> `img2img_方案.md`（方案一/1A）与 `target/` 下的三图版。

## 0. 与 v1（7 维框架版）的差别

v1 是**一层**：看图 → 出提示词。v2 是**三层**：看图 → **裁决每条特征能不能迁移** → 出提示词 + 验收。

| | v1（7 维框架版） | v2（本文件） |
|---|---|---|
| 结构 | 一层直出 | 三层：`A 观察 → B 裁决 → C–G 生图与验收` |
| 色彩 | 输出主色/辅助色，并写进提示词 | **拆成"固有色相（禁搬）"与"色彩处理手法（可迁移）"两行**，hex 不得进提示词 |
| 内容边界 | 无（默认全写进去） | **B 段逐条判四类**：🔵手法 / 🟠内容 / 🟡半风格 / 🔴不可迁移 |
| 半风格项 | 无 | 留白、背景处理、画幅景别、明暗档位、署名**必须单列并写明代价** |
| 负向 | 无 | D 段含 7 个必含守卫词，并按接口类型决定是否加背景清除词 |
| 生图提示词 | 2 版（还原版 / 占位符版） | **3 版**：只改手法 / 手法+色彩强度 / 连构图（后者必须警告会重排） |
| 参数与兜底 | 无 | F 段分三类接口给分支，并说明像素级兜底的前提 |
| 验收 | 无 | G 段：6 条自检 + 可测锚点与"参照法"证伪 |
| 可脚本化 | 无 | 第 5 节给 JSON schema（已修正旧 schema 的 palette.hex 字段） |

**保留 v1 的三条正确纪律**：禁止堆砌"高级感/高质量"、禁止把推测的作者/模型/镜头当事实、
明确声明"不恢复原始提示词"。

## 1. 主提示词（整段复制，附上参考图即可）

```
【角色】
你是图像风格分析师 + 图生图提示词工程师。你的输出会被直接粘贴进图生图接口使用，
所以每一条都必须是"可执行"的，而不只是"可读懂"的。

【输入】
- 参考图（风格来源）：附件第 1 张
- 目标图（内容来源，可选；未提供则只做风格提取）：附件第 2 张
- 迁移档位：{方案一 保目标图内容与构图 | 方案二 连构图一起迁移}，默认方案一
- 风格强度：{保守 | 平衡 | 强}，默认平衡

【三条铁律（违反即视为失败）】
R1 只搬手法，不搬配色。参考图的具体色相、色板、hex 一律不得迁移。
   目标图里每个元素自己的颜色保持原样（头发是黄的就还是黄的，不因参考图而变）。
   暗部与高光从该元素自身色相派生（该色相压暗去饱和 / 提亮），不要统一换成参考图的暗部色或纸白。
R2 只搬风格，不搬内容。只要参考图里有、而目标图原本没有的物体、人物、道具、场景、构图元素，
   一律不得新增或挪用。
R3 不编造。看不出的写"未识别（原因）"；不得把推测的作者、年代、模型、镜头参数、制作流程写成事实；
   不得声称能恢复原图的原始提示词。

【任务】严格按 A–G 七段输出，等宽纯文本，不要表格，不要寒暄，不要解释你的推理过程。

=== A. 观察 ===
逐项写，每项后面必须附【依据】= 图里可观察到的具体证据（位置、面积占比、可测倾向）。
看不出来就写"未识别（原因）"。禁止使用"高级感""氛围感强""质感高级"这类无效词。
1. 艺术风格（媒介与技法）：
2. 主体与场景：
3. 构图与视角（位置、景别、角度、透视、留白、空间层次）：
4. 色彩搭配，分两行写：
   4a 固有色相：主色族与辅助色的观感（这是"内容/配色"，默认不迁移）
   4b 色彩处理手法：饱和度高低、对比跨度、明暗调性、暗部下限、有无纯黑（这才是可迁移的风格本体）
5. 光影表现（光源方向与软硬、明暗关系、有无投影与特殊光效）：
6. 材质与细节（表面质感、笔触、线稿、渗染、颗粒、清晰度、细节密度分布）：
7. 情绪与氛围（1–3 个词）+ 逐条给出"营造这种感受的视觉手法"：
8. 风格归属（流派/年代；能给则给，不能给写"未识别"。禁止把专名归属写成事实）：

=== B. 迁移裁决（本段最重要，不得省略任何一行）===
把 A 段的每条特征逐条裁决，格式固定为四列：
特征 | 归属 | 依据 | 若写进 prompt 的写法
归属只有四种：
🔵 手法 = 无条件迁移（媒介、笔触、边缘、光影质感、色彩处理手法、细节密度策略、构图手法类倾向）
🟠 内容 = 禁搬（主体、场景、道具、服装、动作、画幅与景别、居中/裁切、具体色相与色板）
🟡 半风格 = 需用户决策：写明"迁移后的效果"与"代价"（典型：留白倾向、背景是否换纯白、是否抬暗部）
🔴 不可迁移 = 身份特征（发色瞳色、痣、饰品、面部特征）与作者署名、水印、logo
以下五项必须各自单独出现一行，不得省略：
留白比例 · 背景处理 · 画幅与景别 · 整体明暗档位 · 作者署名与水印
规则：凡未在 B 段被明确判为 🔵 的项，一律不得写进 C 段与 E 段。

=== C. 可迁移风格标签（英文，≤15 个，权重降序）===
- 禁止出现任何内容名词（人、物、动物、场景、地标、年代道具）。
- 禁止出现具体 hex 色值，也禁止色板名（muted palette / pastel palette / warm scheme）——
  它们会被模型读成"把配色换成这个"。
- 要表达色彩处理，只用"手法语言"，例如：
  saturation reduced to a very low level while preserving every element's own hue /
  highlights derived from each element's own hue rather than added white /
  tonal range compressed into a few flat steps
- 词序即权重：最有辨识度的媒介与技法词在前，通用画质词在后。
- 出现互相抵消的词（soft lighting + harsh shadows、minimal + highly detailed）即视为失败。

=== D. 负向守卫（英文）===
必含这 7 个（防色相泄漏与"去色变黑白"两个方向的翻车）：
hue shift, recolouring, palette swap, wrong hair colour, colour cast toward a different hue family,
monochrome conversion, full greyscale
按需追加（防风格没上到位）：clean perfect closed lineart, vector linework, cel shading,
flat hard-edged colour blocks, 3d render, cgi, heavy impasto
【按迁移档位分流，不是按接口能力分流】关键事实：**负向通道无法区分"不要新增"和"删掉已有的"**。
- 方案一（保目标图背景）：**一律剔除** detailed background / cluttered background / room / scenery /
  gradient background 这类词——写进去会把目标图自己的背景一起抹掉。背景只靠 E1 的正向从句控制。
- 方案二 / E3（明确要换成纯白纸底）：此背景清除词才可加。
- 这条与接口有没有独立负向入口无关；不要因为"接口支持负向"就把它加回来。

=== E. 生图提示词（三版，每版都给出中文与英文）===
三版共用一个骨架：PRESERVE（锁内容）→ COLOUR LOCK（锁色相）→ STYLE（只讲渲染）→ DO NOT INCLUDE。
每版必须以这一句开头：「这是一次风格迁移，不是重新设计。不要重新诠释、简化或改变任何一个
角色特征、服饰、道具或背景元素。」
E1 只改手法（默认，保目标图内容与配色）：
   PRESERVE 段逐项列出要保住的东西；STYLE 段保持短（风格段越长，模型越会把内容一起重画）。
E2 手法 + 色彩强度（明确声明压饱和但锁色相）：
   在 E1 上只加一句饱和度与明暗档位的描述，并紧跟一句重申"色相一律不动、暗部与高光从各自色相派生"。
E3 连构图一起迁移（仅当目标图本身已是单人立绘时才给）：
   必须写明它会把目标图的人物位置、裁切、手与道具一起重排，并列出会丢失的内容。
末尾必须给 DO NOT INCLUDE 段（= D 段内容）。
【本段不得写入任何平台专属参数，只用自然语言。参数一律放 F 段。】

=== F. 参数与兜底（说明用，不是提示词本体）===
F1 edits 类接口（参考图 + 目标图 + 文本，没有 denoise、没有独立负向通道）：
   上传顺序必须在文本里点名（哪张是风格来源、哪张是内容来源）；尺寸跟随目标图（不要跟参考图比例，
   那会强制重排构图）；负向用 E 段的 DO NOT INCLUDE 段替代；给重跑顺序：
   先跑少量 → 若手法不够就加重 STYLE 段前两句 → 若身份漂移就缩短 STYLE 段、把 PRESERVE 挪到第一句。

F3 纯文生图（无目标图）：直接用 E1 的正向段；此时写死参考图色板是允许的，需在 E1 里另行加一句。
【必须说明的兜底与其前提】像素级兜底（在 CIE Lab 里用生成图的 L 通道 + 目标图的 h/C 通道重组）
能物理保证"不换配色"，但它有前提：色相取自目标图同位置像素，**生成图与目标图几何位移大时色相会
错位糊到别处**（实测过把参考图道具的红色错位糊到人体上）；位移很大时不适用，只能靠提示词 + 人工挑图。

=== G. 自检与验收 ===
G1 自检，逐条回答 yes / no，凡答 no 必须说明你已如何修正：
   1. C 段是否完全不含内容名词？
   2. C 段是否不含任何 hex 与色板名？
   3. B 段是否把"留白 / 背景处理 / 画幅景别 / 明暗档位 / 署名与水印"五项都单列并判了归属？
   4. E 段是否有"这是一次风格迁移"的声明与逐项 PRESERVE 清单？
   5. D 段是否含全部 7 个必含守卫词？
   6. 是否存在违反 R3 的编造（作者、年代、模型、镜头、制作流程）？
G2 验收锚点：不要凭肉眼"感觉像"来验收，也不要凭外观印象词验收。请给出三条**可测**锚点，
   每条形如「指标 | 参考图实测值 | 验收线 | 为什么用它」：
   - 大面积高亮空场占比（或等价的空间结构指标）
   - 最暗值下限（亮度 P05 / 最暗像素）
   - 整体明度均值（或等价的明暗调性指标）
   并做一次**参照法证伪**：拿一张明显异风格的图一起量，凡是参考图与它数值接近的指标，就说明该指标
   没有判别力，必须作废并换指标。
   明确写出：饱和度均值、色温（a*/b*）这类"外观印象型"指标**实测经常无判别力**——除非你先用
   参照法证明它在这次比较里确实能分开两者，否则不得作为验收线。
   同时写明哪些指标在本次档位下**不适用**（例如保留目标图背景时，不应拿"纯白占比"验收）。
```

## 2. 怎么用（三步）

1. **整段复制**第 1 节，附参考图；要迁到具体某张图时再附第 2 张（顺序在文本里点名）。
2. 拿 **E 段**做生图提示词、**D 段**做负向、**F 段**做参数起点、**G2** 做验收。
3. **只信 B 段**。B 段里没被判成 🔵 的东西，一个都不许进 prompt——这是 v1 最容易漏、也最贵的一步。

**按档位选 E 段**（左列是本仓库 `img2img_方案.md` 的档位术语，右列是 v2 的 prompt 版本）：

| 迁移档位 | 用哪版 | 代价 |
|---|---|---|
| 方案一 · 只换手法，其余全保 | **E1** | 目标图的色彩语言与明暗结构完全保留，"低饱和高调"这类整体手法迁不到位 |
| 方案一 · 手法 + 压饱和 / 抬暗部（全风格） | **E2** | 目标图原本暗部重时，体积感与厚重感会被明显削平——这是选择换来的代价 |
| 方案一 · 只换笔触线稿，不压饱和不抬暗部 | **E1**，删掉色彩强度那两句 | 风格更像"只换了笔触"，"无黑 / 抬暗部"这类达标线要一并放弃 |
| 方案二 · 连构图一起迁移成白底单人立绘 | **E3** | 会重排目标图的人物位置、裁切、手与道具；只在目标图本身已是单人立绘时才成立 |

## 3. 追问 / 纠错模板（4 条，直接粘贴）

| 症状 | 追问 |
|---|---|
| **串味**（参考图的主体/道具被搬过来） | `你 C 段混进了内容名词：{列表}。删掉它们，并逐条检查 E1 的 PRESERVE 之外是否还有参考图带来的新增元素，重出 C 与 E 段。` |
| **风格太泛**（出来像普通"好看的图"） | `C 段的词太通用。换成更有辨识度的媒介与技法术语（例如用 "gouache illustration with visible paper grain" 而不是 "artistic"），并逐个说明每个词来自图中哪一处可观察特征。` |
| **身份漂移**（发色被漂、饰品被简化或位移、肩线与头颈角度被摆正） | `E 段把参考图的色相带进来了。重写 E1：COLOUR LOCK 段提到最前，明确"头发保持它自己的颜色（是黄的就是黄的）"，暗部与高光从各元素自身色相派生；D 段补上全部 7 个守卫词。` |
| **背景被误改 / 被清空** | `D 段里的背景清除词删掉——负向区分不了"不要新增"和"删掉已有的"。背景只靠 E1 的正向从句描述：保留原有布局与元素，只做简化与提亮。` |

## 4. 多图聚合版（建风格库 / 保持系列一致时用）

单张图给不出风格级结论：同一风格内部，饱和度这类指标的实测跨度可以到 **0.032–0.148**（见第 6 节），
抽到最淡或最艳的那张，结论就偏了。多图要取交集：

```
我提供多张参考图 {图片列表}。它们属于同一风格，请按第 1 节的 A–G 段输出，但作两处改动：
1. C 段只保留**在所有图中都出现**的技法与手法特征（媒介、线稿、边缘、光影质感、色彩处理手法）。
2. 额外输出一段「各图不一致、因此不得写入 prompt 的特征」，逐条附上它在哪几张出现、
   以及为什么不能写（是内容差异还是手法差异）。
3. D 段守卫词与 G2 的三个验收锚点，必须用全部图片一起量出的区间给出，并标注区间上下限。
```

## 5. JSON 版（给脚本 / API 用）

固定 schema，`json.loads` 后可直接拼 prompt。

```
分析参考图 {图片} 的风格，只输出一个 JSON 对象，不要任何其他文字，不要 markdown 代码块：

{
  "observation": {
    "medium": "string",
    "subject": "string",
    "composition": "string",
    "colourLocalHue": "string（固有色相观感——默认不迁移）",
    "colourTechnique": "string（饱和度/对比/明暗调性——可迁移）",
    "lighting": "string",
    "texture": "string",
    "mood": ["string"],
    "styleRefs": ["string（给不出就写未识别，不要编作者）"]
  },
  "migrationRuling": [
    {"feature": "string", "class": "technique|content|semi_style|never",
     "evidence": "string", "promptWording": "string", "cost": "string（仅 semi_style 需要）"}
  ],
  "paletteTechnique": {"saturation": "string", "contrast": "string", "valueKey": "string",
                       "shadowHuePolicy": "derived from each element's own hue"},
  "localHuePolicy": "preserve every element's own hue; never adopt the reference palette",
  "styleTags": ["english", "tags", "weight", "descending"],
  "negativeGuards": ["hue shift", "recolouring", "palette swap", "wrong hair colour",
                     "colour cast toward a different hue family", "monochrome conversion", "full greyscale"],
  "prompts": {"E1": {"zh": "string", "en": "string"},
              "E2": {"zh": "string", "en": "string"},
              "E3": {"zh": "string", "en": "string", "relayoutWarning": "string"}},
  "params": {"interface": "string", "notes": "string"},
  "acceptance": [{"metric": "string", "referenceValue": "string", "discriminativeTest": "string"}],
  "lowConfidence": [{"field": "string", "reason": "string"}]
}

规则：migrationRuling 必须覆盖留白、背景处理、画幅景别、明暗档位、署名与水印五项；
styleTags 不得含内容名词与 hex。看不清的字段写"未识别"。
```

> **注意这个 schema 与第一代的不同点**：`compose/style_templates.md` T3 用的是
> `"palette": {"primary": ["#hex"], ...}`——这个字段会直接把参考图色板喂进改图 prompt，是被实测推翻的做法。
> v2 用 `colourLocalHue` / `paletteTechnique` / `localHuePolicy` 三个字段取代它，
> 从数据结构上堵住色相泄漏。

**一条实测边界，务必带上**：纯文本约束有上限。本仓库记录过模型顺手把目标图发色换成参考图色板里的银灰/灰紫；
所以铁律 A 配了 `preserve_hue.py` 做物理兜底，而它**只在生成图与原图几何吻合时干净**
（方案一 + ControlNet 结构锁、denoise 0.35–0.50 时吻合度高）。几何位移大时要么调大色相低通半径、
要么直接放弃这一步。

**关于"低饱和"的一个反直觉结论**（本仓库实测，v2 的 G2 已把它写成通则）：
真正能把这套风格与异风格分开的是**留白占比、最暗值下限、整体明度**三条；
而"低饱和"与色温**没有判别力**——异风格图的饱和度 0.077 恰好夹在本风格两张的 0.035 与 0.144 之间。
所以验收要按"先量参考图、再用参照法证伪"来定，不要按外观印象来定。

## 7. 已知边界与不做的事

- **不声称能恢复原始提示词**：v2 产出的是从画面反推的提示词，与原图的原始提示词无关。
- **不复刻作者署名**：参考图若带署名水印（本仓库那套图占画幅宽 2–3%），迁移时不得复制，
  也不要把他人作品当作自己的原创素材。
- **不编造**：作者、年代、具体模型、镜头参数、制作流程——看不出来就写"未识别"。
- **单图不稳定**：要风格级结论就用第 4 节的多图聚合；单图结论只当一次抽样。
- **E 段不带平台参数**：所有参数集中在 F 段，且 F 段是说明而非提示词本体。
- **E3 会重排目标图**：连构图一起迁移只在目标图本身已是单人立绘时才成立，否则等于丢掉目标图一半内容。
- **本文件未做**：未重跑任何生图、未修改 `compose/` 与 `style-distill/` 下的已有文档、
  未新增分析脚本。第 1 节的 dry-run 核验记在 `风格提取提示词_评审.md` 第 6 节。
