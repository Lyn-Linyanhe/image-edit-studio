# Grok 生图通道的建立：从验证到定稿的完整记录

> 2026-10-06 建立并实测定稿。本文记录 Grok 通道（image-direct.geiliapi.com，grok-imagine 系）
> 的架构、实测约束、事故复盘，以及与 GPT 通道（同站 gpt-image-2.5 系）的分工结论。

## 一、通道架构

同一中转站（geiliapi）提供两套生图引擎，通过分离的环境变量配置：

| | GPT 通道 | Grok 通道 |
|---|---|---|
| 端点 | `RELAY_BASE_URL` | `RELAY_GROK_BASE_URL` |
| Key | `RELAY_API_KEY` | `RELAY_GROK_API_KEY` |
| 模型 | `gpt-image-2.5-sunburst`／`-flare` | `grok-imagine`（t2i）／`grok-imagine-edit`（i2i） |
| 画风 | 水彩灰调渲染（贴参考图像素） | 平涂动画风（Grok 自有风格） |

## 二、实测约束（五坑，全部一次踩过并留档）

1. **单图限制**：`image` ＋ `image[1]` 同时发送 → HTTP 400。双图任务走 GPT 通道；
2. **尺寸白名单**：1k 档仅 `1024x1024`——1024x1536 → 400；
3. **image 字段必须 `image.png`＋`image/png`**：`base.jpg`＋`image/jpeg` → 400
   （内容是 JPEG 配 PNG 头反而能过——按文件名/类型头判断）；
4. **间歇 400**：同一份载荷连续 4 次脚本报 400、内联重发 2/2 成功——疑似频控。
   400 未计费可人工隔窗重试；脚本内不自动重试；
5. **结果只回 URL**（imgen.x.ai）：直连 TLS EOF、代理直下 403——需
   代理＋浏览器 UA＋断点续传三件套下载（`run_round.download` 已特判该域名）。

## 三、通道分裂事故（已修复）

**现象**：ZCode 进程继承的环境是会话启动时的注册表快照（geiliapi），用户后来把注册表
更新为 micuapi——进程环境不随注册表热更新，导致 `run_round.py` 主链路（走进程环境）
与一次性脚本（winreg 直读注册表）**打向两个不同的站**，混用一整天而不知情。

**修复**：注册表固化为用户确认的正确通道（geiliapi），旧值备份；
**教训**：开工前必须核对进程 `os.environ` 实际值（base＋key 前缀），每笔调用的
report/ledger 记录实际 host——ledger 已新增 `host` 字段。

## 四、mask＋ref 组合的坑（双图修复必须手动组包）

CLI 的 `--mask --mask-primary --ref` 会**静默丢弃 ref**（载荷重建只保留主图与 mask）。
双图修复（涂红主图＋alpha 蒙版＋画风参考图）需手动组包三字段：

```python
files = {
    "image": ("painted.png", painted_png, "image/png"),   # 蒙版区涂红的主图
    "mask": ("mask.png", alpha_png, "image/png"),          # alpha 蒙版
    "image[1]": ("style_ref.jpg", style_jpg, "image/jpeg"), # 画风参考
}
```

实测可行（2026-10-06，脸部画风修复），但**双图模式下模型重绘幅度远超单图 mask**——
红区外的「保留」指令会被参考图稀释，全图可能被重诠释。适合大修，不适合最小干预。

## 五、`input_fidelity=low`：画风迁移的正解参数

gpt-image 系的原生参数（GPT 通道特有，Grok 无此概念）：

- `low`：明确告诉模型「不要照抄输入图的内容」，输入图退化为风格/氛围指导；
- 一次调用同时达成「画风保真＋内容全新」——在此之前尝试的两段式、裁片引导、
  草图三段式、本地 ComfyUI 全部绕路（详见 LESSONS 2026-10-06 各条）；
- **验证**：跨季节场景（夏日竹林模板 → 雪景/月夜/樱花产出）全部成功，
  樱花版为美术上限参照；
- **判读规则**：跨内容对比按「亮区色」验收（夜景整体必然压暗）。

## 六、三组对照实验：提示词质量与通道正交

同一场景（雪夜灯火）三个版本的重合率（WD14 tag 与模板的重合度）：

| 组 | 提示词 | 通道 | 重合率 |
|---|---|---|---|
| 1 | 场景 v1（无露脸/发丝约束） | Grok | 0.415 |
| 2 | 场景 v2＋完整约束 | GPT | 0.386 |
| 3 | 场景 v2＋完整约束 | Grok | **0.556** |

**结论：提示词质量与通道正交。** 通道决定画风格（Grok 平涂 vs GPT 水彩渲染），
提示词决定执行质量（露脸、发丝组织、干净色块）——好提示词跨通道可移植。
批量实战验证：GPT 通道 15 张零乱线圈（发丝正向约束生效）、Grok 通道 15 张零缺陷。

## 七、通道分工结论（用户审美判定后定稿）

- **用户判定**（同提示词双通道对比）：Grok 平涂动画风优于 GPT 水彩风——画风「好」的
  定义权在用户眼睛，不在「像不像参考图」；
- **分工**：同风格批量任务默认 **Grok 通道**（干净稳定零缺陷，方图 1024×1024）；
  需要水彩质感或竖图时用 **GPT 通道**（`input_fidelity=low`）；
- 提示词使用两通道通用版 v2（场景＋露脸条款＋发丝正向＋干净色块＋亮区指令）。
